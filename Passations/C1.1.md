> conserve la revue initiale telle que produite ; ses prescriptions (« ne pas commencer

> Date de la revue : 2026-11-01. Périmètre : changements **non commités** du dépôt de code

> l'**USB principal** (`Serial`), qui remplace `Serial8` (V-1-07 : plus de broches à

## Objectif

Le paquet `1.1` doit fournir et démontrer :

1. un banc PlatformIO autonome par capteur (BNO085, BMP581), sans assertions dans le
   programme de banc ;
2. la trame canonique unique en `VALIDATION` (en-tête, une ligne par événement, unités,
   précisions, métadonnées) et un puits fichier simulé pour les tests ;
3. les algorithmes purs (décodage, conversions, configuration IIR/OSR, statistiques)
   couverts par des tests natifs ;
4. `CapteursConfig.h` comme source unique de configuration, avec tous les drapeaux
   réellement surchargeables par `build_flags` ;
5. `CapteursState` comme mémoire d'entrée pure, prête pour le paquet `1.2` ;
6. le contrat du tampon d'émission et de la clôture (ligne entière ou rien, `dropped`,
   `flush`/`close`, clôture unique) ;
7. la machine de phases `INIT → … → HALTED` et la LED 13 conformes au §1.3.3 ;
8. les mesures et critères `M1`/`M2` (σ, fréquence réelle, campagne IIR/OSR/ODR), puis
   `M3`/`M4` pour la consolidation et la feuille verte du paquet `1.2`.

## Ce qui fonctionne

### Builds et tests vérifiés

- `pio test -d lib/sensors -e native` : **63 cas sur 63 réussis** (7 suites, 10,1 s).
- `pio test -d lib/sensors -e native_cible` : **2 cas sur 2 réussis**.
- `pio run -d bench/test_bno085 -e teensy41` après `-t clean` : **SUCCESS** (15,5 s),
  RAM1 14,7 % (77 088 o), RAM2 27,6 % (144 824 o), Flash 0,8 % (62 236 o).
- `pio run -d bench/test_bmp581 -e teensy41` après `-t clean` : **SUCCESS** (15,0 s),
  RAM1 14,2 % (74 272 o), RAM2 27,6 % (144 800 o), Flash 0,7 % (57 252 o).
- Les seuls avertissements de compilation viennent des bibliothèques tierces
  (`Adafruit BNO08x`, `DFRobot_RTU`, `Wire`), pas de `lib/sensors`. Les drapeaux
  `-Wno-unused-parameter` et `-Wno-format-truncation` masquent toutefois des familles
  d'avertissements dans les bancs ; le second est justifié par le rejet de ligne entière,
  mais il doit rester couvert par les tests de longueur.

### Contrats déjà couverts par les tests natifs

- En-tête et lignes canoniques de la configuration **par défaut** (BNO085 + BMP581) ;
  parité entre deux puits alimentés par le même `formatRecord()` ;
- rejet de lignes entières en cas de débordement, rejet par puits, puits bloquant simulé ;
- clôture unique, métadonnées `# finalize`, `# dropped_records`, `# session_end`,
  `# buffer_warn` ;
- machine de phases (chemin nominal, calibration déjà bonne, timeout, `ARMED_DEGRADE`,
  pré-vol KO, clôture, transitions illégales) ;
- conversions quaternion/Euler, altitude ISA, IIR, `P0`, `rawToPa`/`rawToC`,
  trous de séquence, statistiques et fréquence réelle ;
- `CapteursState` (écriture/lecture, fraîcheur, compteur de séquence, indices hors capacité) ;
- prédicats de configuration, anti-doublon I2C, identités, périodes, source simulée
  interdite hors DEV, périmètre `CAP_TEST_CIBLE`.

### Structure et non-régression

- Le firmware existant (`src/`, `include/`, `main/`, `commun/`, `platformio.ini` racine)
  n'est pas modifié par ce paquet ; les bancs sont séparés et n'utilisent pas d'assertions.
- `lib/sensors` est la future source unique ; les pilotes CMPS12/MPL3115/UWB sont des
  ports fidèles des précédents, laissés hors du champ de test de l'étape 1 (sauf mention
  explicite ci-dessous).
- `CapteursState` est instancié dans les deux bancs (`setImu`, `setAlti`) et non seulement
  testé sur hôte.

## Décisions prises

1. **`lib/sensors` est la source unique** : les bancs ne recopient aucun pilote ; les
   pilotes CMPS12/MPL3115/UWB sont des ports fidèles des précédents, avec les écarts
   explicitement commentés.
2. **Trame canonique unique** : `formatRecord()` est le seul producteur ; les deux puits
   reçoivent les mêmes octets ; le puits fichier simulé sert aux tests, aucune SD physique
   n'est exigée à l'étape 1.
3. **Format des nombres** : le code suit l'exemple du §1.3.1 **sans signe `+`**
   (`%.6f`, `%.3f`), car les tests et l'exemple du document n'ont pas de `+` ; le texte
   `%+.6f` du même paragraphe est une contradiction documentaire à arbitrer (voir §Écarts).
4. **Colonne `qacc` pour RVG laissée vide** : `sh2_RotationVector_t` n'a pas de champ
   `accuracy` en radians ; le statut SH-2 est logé dans la colonne `status`
   (`accuracyGame`). Le `precisionGameRad` déclaré dans `ValsImu` n'est pas rempli.
5. **BMP581** : ODR 50 Hz (`eOdr50Hz`), OSR T×1/P×8, IIR C=15, mode normal ; `P0` est
   une constante de travail `101325 Pa`, à remplacer par le calage au sol.
6. **BNO085** : pas de reset matériel forcé ; réactivation des rapports si `wasReset()`
   (échec non remonté, voir C4) ; pas de FRS/mémoire de calibration à l'étape 1.
7. **Phases** : `requestFinalize()` est volontairement admis depuis `ATTENTE_CALIB` et
   `SAFE` pour les essais de banc (extension documentée dans `session_phase.h`) ; le
   graphe nominal reste celui du §5.2.
8. **CMPS12/MPL/UWB** : consolidation de comportement, sans banc dédié ; l'UWB reste
   désactivé tant que le port `Serial5`/`Serial1` n'est pas arbitré.
9. **Aucune intégration firmware** : le paquet `1.1` ne modifie pas `src/` ni
   `platformio.ini` racine ; l'intégration appartient aux paquets suivants.
10. **`compile_commands.json`** doit être retiré de l'index Git, pas seulement ajouté au
    `.gitignore`.
11. **Port de la trame = USB principal** (`Serial`) — décision 2026-11-01 : `PuitsSerie`
    devient un template (UART ou CDC), le journal DEV passe en métadonnées `# dev:`
    (aucun texte libre sur la liaison) et les variantes DEV des bancs restent documentées
    avec `CAP_DEV_SERIAL_LIBRE=0` (voir Ajout post-revue en tête de note).

## Écarts et contradictions détectés

| Sujet | Documents / code | Écart | Arbitrage proposé |
| :--- | :--- | :--- | :--- |
| Signe des flottants | §1.3.1 dit `%+.6f`, l'exemple et les tests n'ont pas de `+` | Contradiction interne au document | Choisir une seule forme ; si l'exemple fait foi, corriger le texte `%+` ; sinon corriger le code et les tests. |
| `qacc` RVG | §2.8 dit « types RV/RVG » ; le code laisse `qacc` vide | Le rapport GRV n'a pas d'accuracy en radians ; le statut 0..3 est dans `status` | Documenter explicitement « qacc vide pour RVG » ou définir une autre colonne ; ne pas laisser l'ambiguïté. |
| Macros surchargeables | §1.2 exige `#ifndef` pour `CAP_*`/`CAP_LOG_*`/`CAP_DEV_*` ; l'annexe A définit `CAP_DEV_PREFLIGHT_SKIP`, `CAP_SESSION_AUTO_START_MS`, `CAP_DEV_REARM` sans `#ifndef` | La règle et le squelette se contredisent ; les `-D` documentés ne gagnent pas | Mettre ces macros sous `#ifndef` dans le header (et l'annexe A) et ajouter un test de préprocesseur. |
| Pré-vol DEV | §1.3.2 dit `CAP_DEV_PREFLIGHT_SKIP` possible ; le code ne peut pas l'activer | Voir B4 | Corriger B4 avant de s'appuyer sur ce contournement. |
| Une ligne par événement | §2.7.3 et §1.3.1 ; masque `recus_` | Deux événements du même type = une ligne | Émettre une ligne par événement ; ajouter un test de rafale. |
| P0 au sol | §5.2 « P0 écrit et reçu » ; `BMP581_P0_PA` constant | Le banc ne cale pas P0 | Décider : constante de référence documentée (altitude absolue) ou calibration au sol ; le cas échéant, implémenter la mesure et la métadonnée. |
| `valid` CMPS12 | §2.6 ; `IMUCMPS12::read()` | `valid` jamais positionné | Corriger le pilote et couvrir par un test natif (payload sans Arduino). |
| Adresse CMPS12 | §1.7.1 et précédent : `newAddr << 1` ; code : brut | Adresse incorrecte | Corriger `changeAddress()` ; garder 20 ms ou justifier 100 ms. |
| `Wire.setTimeOut(25000)` | §5.3 ; API Teensyduino 1.159 sans timeout public | Le code ne peut pas appeler la fonction demandée | Documenter l'écart, utiliser le timeout interne de `WireIMXRT` (15 ms/50 ms) et démontrer `recoverI2CBus()` sur SDA bloqué ; sinon le critère « 0 blocage non récupéré » n'est pas démontré. |
| `compile_commands.json` | §10.6 ; `git ls-files` | Toujours suivi malgré `.gitignore` | `git rm --cached` lors du commit de clôture. |
| Registre `V-1-*` | Voir C17 | `V-1-06`, `V-1-10`, `V-1-12` | Mettre le registre à jour ou aligner le code ; ne pas laisser une valeur `PROVISOIRE V-1-12` absente du registre. |
| Longueurs de ligne | §1.3.1 : 80/80/70/70/70/55 ; code : 96/96/88/88/88/72 | Le code est plus conservateur | Conserver les bornes du code si les tests les vérifient, ou recalculer et mettre à jour le document ; ne pas mélanger les deux jeux. |
| README | « calibration automatique », « démarrage automatique » | Le code ne démarre automatiquement qu'en `ARMED` et ne calibre pas le BNO085 ; B4 rend l'option inopérante | Corriger le README ou implémenter la séquence automatique complète (calibration puis démarrage) en DEV. |
| LED | §5.2/§1.3.3 ; code `P2(3)`/`P2(4)` | Motifs faux pour calibration/dégradé | Utiliser `P3` en calibration, 3 éclairs en dégradé, `P1` sur échec d'init. |
